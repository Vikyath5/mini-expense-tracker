# Contributing Guide

## Branching

Do not commit directly to `main`.

Create a feature branch for every change.

## Pull Requests

All changes must be submitted through a pull request.

Each pull request should:
- Have a clear title
- Contain focused changes
- Be reviewed by the other developer
- Address review feedback before merging

## Commit Messages

Use short imperative commit messages of 50 characters or fewer.

Examples:
- Add expense form
- Fix input validation
- Improve expense layout

## Code Review

Reviewers should provide useful feedback before approving a pull request.
